# 슈미트해머 데이터시트 (웹앱)

슈미트해머(반발경도계) **결과기록지 사진을 올리면** `슈미트해머.xlsx` 예시 양식(KS F 2730 데이터시트)을 자동으로 채워 줍니다.
OCR은 서버 없이 **브라우저 안에서** 돌아가므로 기록지 사진이 어디로도 전송되지 않습니다.

## 실행

```
start.bat            (또는)   node server.mjs
```

브라우저가 `http://localhost:5173/` 으로 열립니다. Node.js 18 이상이 필요합니다(다른 설치물 없음).

> `index.html` 을 더블클릭(file://)하면 OCR 엔진(WebAssembly/모델)을 브라우저가 막아서 **OCR만 안 됩니다**. 값을 직접 입력하면 양식은 채워집니다.
> 배포할 때는 `server.mjs` 없이 이 폴더를 그대로 아무 웹서버에 올리면 됩니다. 서버가 `Cross-Origin-Opener-Policy: same-origin` / `Cross-Origin-Embedder-Policy: require-corp` 헤더를 주면 멀티스레드로 더 빨라지고, 없어도 동작합니다.

### 휴대폰에서 쓰기 (같은 Wi-Fi)

```
start-phone.bat      PC 에서 실행 → 브라우저에 QR 이 뜸 → 폰 카메라로 스캔
```

- 폰과 PC가 **같은 Wi-Fi**여야 하고, `start-phone.bat` 창이 열려 있는 동안만 접속됩니다. (기본 `start.bat` 은 PC 전용이라 폰에서 접속되지 않습니다.)
- 폰에서 `카메라로 촬영` 으로 결과기록지를 찍으면 폰 브라우저 안에서 읽고 양식을 채웁니다. 사진은 PC나 인터넷으로 가지 않습니다.
- 연결이 `http://192.168.x.x` (보안 연결 아님)이라 폰에서는 멀티스레드를 못 써서 PC보다 느립니다 (PC에서 같은 조건으로 측정: 샘플 약 2.5초, 멀티스레드 1.5초).
- 이 방식은 사무실·집 같은 같은 네트워크에서만 됩니다. **현장에서 PC 없이** 쓰려면 이 폴더를 https 웹호스팅(GitHub Pages, Netlify 등)에 올려야 합니다.
- 안 열리면: ① 폰이 LTE/5G·게스트 Wi-Fi가 아닌지 ② 공유기의 '기기 간 격리(AP isolation)' ③ Windows 방화벽에서 Node.js 허용(첫 실행 때 뜨는 창에서 허용).

### 안드로이드 앱(APK)으로 설치 — PC·Wi-Fi 없이 폰 단독 실행

`..\android\dist\SchmidtDatasheet.apk` (약 20MB). 화면·OCR 엔진·모델이 모두 앱 안에 들어 있고 **인터넷 권한이 없어서** 사진이 밖으로 나가지 않습니다.
폰으로 옮기는 방법은 **USB 로 연결해 `..\android\install-usb.bat` 로 설치**하는 것입니다 (QR·링크 다운로드는 쓰지 않습니다).
설치 방법, 다시 빌드하는 법, 서명 키 백업은 `..\android\README.md` 를 보세요.

### 아이폰·안드로이드에 설치해 쓰기 (PWA) — 링크만 열면 됨, 인터넷 없이도 실행

웹앱을 인터넷 주소(https)로 배포하면 휴대폰 홈 화면에 **앱처럼 설치**할 수 있습니다 (서버·PC·USB 케이블 불필요, 앱스토어 심사 없음).
설치하면 OCR 모델까지 휴대폰에 저장되어 **비행기 모드에서도** 인식·저장·PDF 만들기가 됩니다. 사진은 서버로 전송되지 않습니다.

- **아이폰(iOS 16.4 이상)**: **Safari** 로 주소를 열고 → 아래쪽 공유 버튼(□↑) → **홈 화면에 추가**. (카카오톡·네이버 등 앱 안의 브라우저로 열면 추가할 수 없습니다 → 오른쪽 아래 ⋯ → Safari로 열기. 화면 위쪽 안내에 `주소 복사` 버튼이 있습니다.)
- **안드로이드**: 크롬에서 열면 위쪽에 `설치` 안내가 나옵니다 (메뉴 ⋮ → 앱 설치 / 홈 화면에 추가도 가능). USB 로 설치하는 APK 방식은 위 "안드로이드 앱" 절.
- **처음 한 번**은 앱 전체(약 30MB)를 내려받습니다. Wi-Fi 에서 여세요. 이후에는 인터넷이 필요 없습니다.
- **문서는 그 앱 안에만 저장됩니다.** 아이폰은 Safari 탭과 홈 화면에 설치한 앱의 저장소가 서로 달라서, 설치한 뒤에는 **홈 화면 아이콘으로만** 쓰세요(Safari 에서 먼저 만든 문서는 설치한 앱에 보이지 않습니다). 홈 화면에 설치한 앱은 Safari 의 "7일 안 쓰면 사이트 데이터 삭제" 정리 대상이 아닙니다. 그래도 중요한 문서는 `ZIP으로 내보내기`로 보관하세요.
- **PDF·ZIP 내보내기**: 터치 기기에서는 공유 시트가 열려 파일 앱 · 카카오톡 · 메일 · AirDrop 등으로 바로 보낼 수 있습니다.
- **새 버전**: 새 버전이 배포되면 위쪽에 알림이 뜨고 `지금 적용`을 누르면 바뀝니다 (문서는 그대로).
- 인터넷 연결 상태에서 앱을 다시 열 때마다 새 버전이 있는지 확인합니다.

**배포하는 방법** (저장소 소유자용): `main` 브랜치에 푸시하면 GitHub Actions(`.github/workflows/pages.yml`)가 `node app/tools/build-pwa.mjs _site` 로 배포용 폴더를 만들어 GitHub Pages 에 올립니다. 저장소 설정의 Pages 소스를 "GitHub Actions"로 지정해야 합니다.
직접 만들어 보려면 `cd app; node tools/build-pwa.mjs _site` 후 `ROOT=_site node server.mjs 5175` 로 열어 보세요 (`localhost` 는 서비스 워커가 허용되는 보안 주소). 이 빌드는 파일 내용으로 버전을 정하므로, 파일이 하나라도 바뀌면 설치된 앱이 새 버전으로 교체됩니다.
아이콘은 `npm run icons`(sharp 필요)로 다시 만들 수 있습니다 — 아이폰용 180×180 `apple-touch-icon.png` 는 모서리를 둥글게 깎지 않은 정사각형이어야 합니다(iOS 가 직접 깎음).
## 사용 방법

1. **결과기록지** — 사진을 끌어다 놓기 / 클릭해서 선택 / `Ctrl+V` 붙여넣기 / 카메라 촬영. (`예시 이미지로 체험` 버튼으로 바로 시험해 볼 수 있습니다.)
2. **측정값 확인** — 읽은 R01~R20, ANGLE, 기록지의 AVERAGE와의 일치 여부가 나옵니다. 틀린 값은 칸에서 직접 고치면 양식에 바로 반영됩니다. 칸에 포커스를 두면 사진에서 그 행이 하이라이트됩니다. 사진이 돌아가 있으면 `회전` 버튼.
3. **시험 정보** — 현장명, 시험위치, 타설일, 시험일, 시험자, 감리원. 재령일과 재령계수는 타설일~시험일로 자동 계산되며 직접 고칠 수도 있습니다. 양식의 "재령보정계수 : 49 일" 옆에는 그 재령의 재령계수(α)도 함께 적힙니다. **현장명·시험위치·시험자·감리원은 이 기기에 기억**되어 다음에 열면 자동으로 채워지고, 최근에 쓴 현장명·시험자·감리원은 입력칸 아래 버튼으로 한 번에 고를 수 있습니다 (`×`로 목록에서 삭제). 폰·PC·앱은 저장소가 각각이라 서로 공유되지 않습니다.
4. **사진대지** — 시험 사진을 넣으면 사진대지 양식에 들어갑니다 (아래 "사진대지" 참고).
5. 오른쪽 양식을 확인하고 아래 작업 막대에서 **PDF 저장**(A4 가로 2쪽: 데이터시트 + 참고표) 또는 **인쇄**. 타점 원의 중심 간격은 가로·세로 모두 **3cm** 로 인쇄됩니다 (A4 가로, 배율 100%).

## 사진대지 (4번 카드)

`슈미트/사진대지.xlsx` 양식(A4 세로, 한 쪽에 사진 칸 2개)을 그대로 옮겼습니다. 열 너비·행 높이를 엑셀 값(pt)에서 가져와 배치했고(`js/photosheet.js`),
양식 미리보기 맨 뒤에 붙습니다. 사진이 없으면 사진대지 쪽은 나타나지 않습니다.

- **사진 넣기**: `사진 추가`(여러 장 선택 가능) 또는 `카메라로 촬영`. 카드에 사진을 끌어다 놓아도 됩니다. 사진은 긴 변 1600px JPEG 로 줄여 저장합니다.
- **자동으로 채워지는 칸**: 시험위치·타설일·시험일은 3번 시험 정보, 맨 아래 오른쪽 현장명도 3번의 현장명입니다. 날짜는 양식처럼 `2026. 08. 03` 형식.
- **시험내용**은 4번 카드에서 직접 적습니다 (기본값 "콘크리트 반발경도 확인" — 양식의 예시 문구).
- **쪽 구성**: 사진 2장당 한 쪽 (`1쪽 사진-1`, `1쪽 사진-2`, `2쪽 사진-1` …, 최대 30장). `◀ ▶` 로 순서를 바꾸고 `✕` 로 뺍니다. 사진이 들어간 칸은 "사진-N" 안내가 사라집니다.
- **사진 배치**: `칸에 맞춤`(사진 전체가 보이고 남는 곳은 흰색) / `칸 채우기`(칸을 꽉 채우고 가장자리가 잘림).
- **PDF·인쇄**: `PDF 저장`은 데이터시트·참고표 2쪽(A4 가로) 뒤에 사진대지(A4 세로)가 이어집니다. 브라우저 인쇄도 용지 방향이 쪽마다 바뀝니다.
- **인쇄 머리글·바닥글**: 회사 양식에 인쇄되는 머리글(오른쪽 위)·바닥글(맨 아래 오른쪽)이 있으면 4번 카드의 `인쇄 머리글·바닥글`에 한 번 적어 두세요. 사진대지의 같은 위치에 들어갑니다. 이 기기에만 저장되고 모든 문서에 적용되며(코드에는 어떤 문구도 들어 있지 않습니다), 비워 두면 인쇄되지 않습니다.
- 문서와 함께 저장되며(문서함에서 다시 열면 사진이 복원됨), ZIP 으로 내보내면 `날짜/NN_현장_위치_사진-1.jpg` 로 들어가고 다시 가져올 수 있습니다.
## 문서함 — 시험일별로 모아 관리하고 한꺼번에 내보내기

- **자동 저장**: 측정값이 생기면 잠깐 뒤 문서함에 저장되고, 화면을 떠나거나 앱을 닫을 때도 저장됩니다. 사진만 있고 값이 없는 문서는 `저장` 을 눌러야 저장됩니다. `새 문서` 는 현장명·시험자·감리원을 유지한 채 비웁니다. 저장된 문서를 보던 중 새 사진을 올리면 새 문서로 시작해 이전 문서가 덮어써지지 않습니다.
- **문서함 탭**: 시험일별(최근 날짜 위) 목록. 문서마다 현장명·시험위치·시험자, R₀, Fc, 확인 필요 표시(재시험·평균 불일치·타설일 필요 등). 검색, 열어서 수정(사진·인식 박스도 복원), 여러 건 선택해 삭제.
- **사진으로 여러 장 추가**: 사진을 여러 장 고르면 공통 정보(시험일 또는 사진 파일 날짜, 현장명, 시험자, 감리원, 타설일)를 한 번만 입력하고 한 장씩 읽어 문서로 저장합니다. 기록지가 아닌 사진은 사유와 함께 건너뜁니다. (작성 화면의 사진 선택·끌어다 놓기에서 여러 장을 골라도 같습니다.)
- **ZIP으로 내보내기**: 선택한 문서 또는 `이 날짜 내보내기`. 구성: `날짜별 폴더/NN_현장_위치.pdf`(데이터시트 2쪽 + 사진대지), `…_기록지.jpg`, `…_사진-N.jpg`(사진대지 사진), `목록.csv`(엑셀용), `데이터.json`(다시 가져오기용). 양식 PDF·사진 포함 여부는 선택할 수 있습니다.
- **ZIP 가져오기**: 내보낸 ZIP(또는 데이터.json)을 다시 불러옵니다. 같은 문서는 더 나중에 고친 쪽을 남기고, 이미 최신이면 건너뜁니다.
- 문서는 **이 기기의 브라우저/앱 저장소(IndexedDB)** 에만 저장되며 폰·PC·앱끼리 공유되지 않습니다. 옮기거나 백업하려면 ZIP 으로 내보내세요.

## 계산 규칙 — 양식의 안내문 그대로

| 단계 | 내용 |
| --- | --- |
| 이상값 제외 | 20개 평균의 **±20%를 벗어난** 값은 제외하고 나머지로 평균을 다시 구함 (경계값은 제외하지 않음). 제외값이 **4개 이상이면 전체 폐기 → "재시험"** 표시 |
| 타격방향 보정 | 양식의 보정표(+90 / +45 / −45 / −90°, R=10~60)로 ΔR 계산. R 사이는 선형보간, 표에 없는 각도(±15·30·60°)는 인접 각도 사이를 선형보간(근사, 경고 표시). 표의 '-' 칸은 R=20 값으로 대체(경고) |
| 반발경도 R₀ | (제외 후 평균) + ΔR, 소수 첫째 자리 |
| 재령계수 α | 양식의 재령표(4~3000일). 표에 없는 재령일은 선형보간 |
| 압축강도 Fc | `(7.3·R₀ + 100) × 0.098` (MPa) → 여기에 α를 곱함 |

양식의 `Fc = (7.3R₀+100)×0.098 = 7.3x( R₀ )+100 = [  ] x 재령계수 = [  ] MPa` 에서 첫 번째 빈 칸에는 **×0.098까지 곱한 값(MPa)** 을 넣습니다. 소속 기관의 기재 방식이 다르면 `js/calc.js` 의 `res.A` 한 줄만 바꾸면 됩니다.

양식의 표(재령표, 보정표)는 `슈미트해머.xlsx` 에서 그대로 옮겼습니다 → `js/tables.js`.

## OCR 구성

**엔진: PaddleOCR PP-OCRv4 (Apache-2.0) 를 ONNX Runtime Web(WASM)으로 실행.** Tesseract.js 도 비교했는데, 이 기록지의 도트매트릭스 글꼴과 슬래시 0에서는 20행 중 최대 10행만 맞았고(전처리를 바꿔 여러 번 시도) PP-OCRv4 는 20행 모두 맞았습니다.

```
이미지 ─ 검출(DB) ─ 글줄을 회전 사각형으로 ─ 똑바로 펴서 ─ 인식(CRNN+CTC) ─ 기록지 해석 ─ AVERAGE 로 검증
```

기록지 전용으로 보강한 점 (모두 `js/ocr/`):

- **AVERAGE 검증** — 읽은 값의 평균이 기록지에 찍힌 AVERAGE(소수 첫째 자리 반올림)와 맞으면 정답으로 보고 멈춥니다. 안 맞으면 조건을 바꿔 재시도하고, 끝내 안 맞으면 화면에 경고합니다.
- **글자 제한 디코딩** — 숫자·영문 대문자·몇 개 기호만 허용(중국어 사전 6,000여 자 배제).
- **기울기·회전 보정** — 글줄 기울기를 투영 프로파일로 추정해 회전된 사각형으로 잘라 읽음, 90/180/270° 돌아간 사진은 방향을 찾아 재시도.
- **조명 보정** — 어둡거나 그늘진 사진은 종이 밝기를 추정해 균일화.
- **기록지 영역 확대** — 큰 사진 속에 기록지가 작게 찍혔으면 글줄이 모인 영역만 잘라 확대.
- **가장자리 인쇄 분리** — 기록지 오른쪽의 세로 인쇄(`…CONCRETE TEST HAMMER`)가 행과 붙으면 글줄 열 바깥 픽셀을 지우고 다시 분석.
- **ANGLE** — 외딴 글리프 `0`은 단독으로 읽으면 9/5/G 로 오독하므로, `ANGLE` 과 글리프를 간격을 좁혀 이어붙인 이미지를 여러 변형으로 읽어 다수결. 확신이 없으면 "자동으로 읽지 못함"으로 표시하고 사용자가 고르게 합니다 (그동안 계산은 0°).
- **기록지 판정** — `AVERAGE` 줄도 없고 행 번호도 1부터 이어지지 않으면(그래프·표 사진 등) 기록지가 아니라고 보고, 이미 입력된 값을 건드리지 않은 채 안내만 합니다.

### 검증한 내용

## 알려진 한계

- 형식은 **KAMEKURA 계열 프린터 출력(`R 01 …`, `AVERAGE`, `ANGLE`)** 기준으로 만들고 시험했습니다. 다른 기종의 출력은 `js/ocr/record.js` 의 해석 규칙을 손봐야 할 수 있습니다.
- 기록지가 사진에서 너무 작으면 읽지 못합니다 (위 합성 시험 기준으로 사진 폭의 약 17% 이하). 가까이서 찍거나 기록지 부분만 잘라서 올려 주세요.
- HEIC 사진은 일부 브라우저에서 열리지 않습니다 (JPG/PNG 사용).
- 사진 속 기록지가 심하게 휘었거나 원근 왜곡이 큰 경우는 다루지 않습니다 (기울기만 보정).
- 타격각도 ±15·30·60° 의 보정은 표가 없어 근사값입니다.
