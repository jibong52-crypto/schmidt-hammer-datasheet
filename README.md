# 슈미트해머 데이터시트

슈미트해머(반발경도계) **결과기록지 사진을 찍으면** 브라우저 안에서 OCR 로 값을 읽어 **KS F 2730 데이터시트 양식을 자동으로 채워 주는** 웹앱입니다. 서버가 없고, 사진은 기기 밖으로 나가지 않습니다.

- 앱 주소: `https://jibong52-crypto.github.io/schmidt-hammer-datasheet/`
- 아이폰·안드로이드 홈 화면에 설치해서 앱처럼 씁니다 (아래 "설치해서 쓰기").

## 주요 기능

- **사진 한 장으로 양식 작성** — 결과기록지 사진(카메라 촬영, 사진 선택, 끌어다 놓기, 붙여넣기)에서 측정값 R01~R20, 타격각도(ANGLE), 평균(AVERAGE)을 읽고, 기록지에 찍힌 평균과 맞는지 검증합니다. 잘못 읽은 칸은 직접 고치면 양식에 바로 반영됩니다.
- **KS F 2730 계산 자동화** — 평균 ±20% 를 벗어난 값 제외(4개 이상이면 재시험 표시), 타격방향 보정, 재령계수, 반발경도 R0 와 압축강도 Fc 를 계산해 데이터시트에 채웁니다.
- **사진대지** — 시험 사진을 넣으면 시험 정보와 함께 A4 세로 사진대지(한 쪽에 사진 2칸)가 만들어집니다.
- **문서함 (시험일별)** — 작성한 문서가 시험일별로 자동 저장되고, 검색, 다시 열어 수정, 여러 건 삭제가 됩니다. 기록지 사진을 여러 장 골라 한꺼번에 문서로 저장할 수도 있습니다.
- **ZIP 내보내기 / 가져오기** — 문서를 날짜별 폴더로 묶어(PDF, 사진, 목록 CSV, 다시 가져오기용 데이터) 내보내고, 다른 기기에서 다시 가져옵니다.
- **PDF 저장 / 인쇄** — 데이터시트·참고표(A4 가로)와 사진대지(A4 세로)를 PDF 한 파일로 저장하거나 인쇄합니다.
- **완전 오프라인, 개인정보 안전** — 처음 한 번 앱을 내려받은 뒤에는 인터넷 없이 동작하고, OCR 을 포함한 모든 처리는 기기 안에서 일어납니다 (아래 "개인정보").

## 설치해서 쓰기 (아이폰 / 안드로이드)

앱 주소: `https://jibong52-crypto.github.io/schmidt-hammer-datasheet/`

### 아이폰 (iOS 16.4 이상)

1. **Safari** 에서 위 주소를 엽니다.
2. 아래쪽 **공유 버튼**(네모에 위쪽 화살표)을 누릅니다. 보이지 않으면 오른쪽 아래 ⋯ 메뉴 안에 있을 수 있습니다.
3. **홈 화면에 추가**를 선택하고 **추가**를 누릅니다.
4. 홈 화면에 생긴 아이콘으로 실행합니다. 주소창 없이 앱처럼 열립니다.

- 카카오톡·네이버 같은 **앱 안의 브라우저에서는 설치할 수 없습니다.** 앱 안 메뉴(⋯)에서 **Safari 로 열기**를 고르거나, 주소를 복사해 Safari 에 붙여 넣으세요.
- iOS 16.4 이상이 필요합니다 (OCR 에 쓰는 WebAssembly SIMD 지원).

### 안드로이드

1. **Chrome**(또는 삼성 인터넷 같은 기본 브라우저)에서 주소를 엽니다. 앱 안의 브라우저(네이버, 카카오톡 등)에서는 설치할 수 없으니 메뉴(⋮)에서 다른 브라우저로 여세요.
2. 화면에 뜨는 **설치** 버튼을 누르거나, 브라우저 메뉴(⋮)에서 **앱 설치**(또는 **홈 화면에 추가**)를 선택합니다.

PC 없이 폰 단독으로 쓰는 APK(WebView 앱)도 있습니다. APK 파일은 저장소에 올리지 않고 직접 빌드합니다 (`android/README.md`).

### 처음 실행할 때 알아둘 것

- **처음 한 번은 인터넷(Wi-Fi 권장)이 필요합니다.** 앱과 OCR 모델 약 30MB 를 기기에 내려받고, 그 뒤로는 인터넷 없이 동작합니다. 설치한 뒤 비행기 모드에서 한 번 열어 보면 준비가 끝났는지 확인할 수 있습니다.
- 새 버전이 올라오면 화면에 "새 버전이 준비되었습니다" 안내가 뜨고, **지금 적용**을 누르면 바뀝니다.
- 결과기록지는 기록지 전체가 화면에 크게 보이게 찍어 주세요.

## 사용 방법

1. **결과기록지** 사진을 올립니다 (`카메라로 촬영` 또는 사진 선택). 처음 써 볼 때는 `예시 이미지로 체험` 버튼을 눌러 보세요.
2. 읽어 낸 **측정값**을 확인합니다. 틀린 값은 칸에서 직접 고칩니다.
3. **시험 정보**(현장, 시험위치, 타설일, 시험일, 시험자 등)를 입력합니다. 재령은 타설일과 시험일로 자동 계산됩니다.
4. 필요하면 **사진대지**에 시험 사진을 넣습니다.
5. 오른쪽 양식을 확인하고 **PDF 저장** 또는 **인쇄**를 누릅니다. 작성한 문서는 **문서함**에 자동으로 저장됩니다.

화면별 자세한 설명, 계산 규칙, OCR 구성은 [`app/README.md`](app/README.md) 를 보세요.

## 저장 위치와 백업

- 작성한 문서와 입력값은 **그 기기의 브라우저(또는 설치한 앱) 저장소에만** 저장됩니다. 서버나 계정이 없어서 폰, PC, 앱끼리 자동으로 공유되지 않습니다.
- 브라우저의 사이트 데이터를 지우거나 홈 화면의 앱을 삭제하면 **저장된 문서도 함께 사라집니다.** 시크릿(사생활 보호) 모드처럼 저장소를 쓸 수 없는 환경에서는 문서가 그 접속 동안만 유지됩니다.
- 그래서 중요한 문서는 **문서함의 `ZIP으로 내보내기`** 로 파일을 만들어 PC 나 클라우드에 따로 보관하세요. 다른 기기로 옮기거나 복구할 때는 같은 문서함의 `ZIP 가져오기` 를 씁니다.
- iOS 는 Safari 탭에서 쓴 데이터와 홈 화면에 추가한 앱의 데이터가 따로 저장되어 서로 보이지 않을 수 있습니다. 설치한 뒤에는 홈 화면 아이콘으로만 쓰세요. 또 Safari 탭으로만 쓰면 오래 열지 않은 사이트의 데이터를 iOS 가 정리할 수 있으니, 홈 화면에 추가해 쓰고 ZIP 백업도 해 두는 것이 안전합니다.

## 개인정보

- 결과기록지 사진, 시험 사진, 입력한 시험 정보와 문서는 **서버로 전송되지 않습니다.** 이 앱에는 서버, 계정, 로그인, 분석(추적) 코드가 없고 OCR 도 기기 안에서(WebAssembly) 실행됩니다.
- 통신은 앱 파일(화면, OCR 모델)을 처음 내려받거나 새 버전이 있는지 확인할 때뿐이며, 이때도 사진이나 입력값은 보내지 않습니다. 앱 파일은 GitHub Pages 에서 내려받습니다.
- 안드로이드 APK 는 인터넷 권한 자체가 없습니다.

## 개발자용

필요한 것: Node.js 18 이상 (20 권장). 웹앱은 빌드 도구 없이 정적 파일 그대로 동작합니다.

### 로컬에서 실행

```
node app/server.mjs             # http://localhost:5173/   (Windows: app\start.bat)
node app/server.mjs --lan       # 같은 Wi-Fi 의 폰에서도 접속, QR 표시   (Windows: app\start-phone.bat)
```

`index.html` 을 파일로 직접 열면(file://) 브라우저가 OCR 엔진을 막으므로 반드시 서버로 여세요.

### 단위 시험

```
cd app
npm install        # 시험 전용 devDependencies (onnxruntime-node, sharp). OCR 회귀 시험에 필요
npm test
```

### 배포용 빌드 (PWA)

```
node app/tools/build-pwa.mjs _site
```

`app/` 에서 배포에 필요한 파일만 `_site/` 로 복사하고, 서비스 워커가 읽는 `precache.js`(버전 + 미리 저장할 파일 목록)를 만듭니다. 결과를 로컬에서 확인하려면 `ROOT` 를 `_site` 로 지정해 서버를 띄웁니다.

```
ROOT=_site node app/server.mjs 5175                    # bash
$env:ROOT = '_site'; node app/server.mjs 5175          # PowerShell
```

### GitHub Pages 배포

저장소 Settings > Pages 의 Source 를 **GitHub Actions** 로 바꿔 두면, `main` 에 push 할 때마다 `.github/workflows/pages.yml` 이 위 빌드를 실행해 배포합니다 (Actions 탭에서 수동 실행도 가능). 단위 시험은 배포 워크플로에 넣지 않았으니 배포 전에 로컬에서 실행하세요.

### 안드로이드 APK

`android/` 에 웹앱을 WebView 로 감싼 앱의 소스와 빌드 스크립트가 있습니다 (Gradle 없이 PowerShell 로 빌드). 서명 키(`android/signing/`)와 결과물(`android/dist/`)은 저장소에 포함되지 않습니다. 빌드와 설치 방법은 [`android/README.md`](android/README.md) 를 보세요.

## 사용한 오픈소스

| 구성요소 | 용도 | 라이선스 |
| --- | --- | --- |
| PaddleOCR PP-OCRv4 (글자 검출·인식 모델, 글자 사전) | OCR (ONNX 변환본은 npm `@gutenye/ocr-models`) | Apache-2.0 (변환본 패키지는 MIT) |
| ONNX Runtime Web | 브라우저에서 모델 실행 (WebAssembly) | MIT |
| qrcode-generator | 같은 Wi-Fi 접속용 QR (로컬 서버 전용) | MIT |

출처, 버전, 자세한 고지는 [`app/NOTICE.md`](app/NOTICE.md) 를 보세요. 검출 후처리, 글줄 기울기 추정, 글자 디코딩, 기록지 해석은 이 저장소에서 직접 구현했습니다 (`app/js/ocr/`).

## 알려진 한계

- 기록지 출력 형식(`R 01 …` 행과 `AVERAGE`, `ANGLE` 줄이 있는 프린터 출력)을 기준으로 만들고 시험했습니다. 다른 기종의 출력은 인식 규칙(`app/js/ocr/record.js`)을 손봐야 할 수 있습니다.
- 기록지가 사진에서 너무 작으면 읽지 못합니다. 가까이서 찍거나 기록지 부분만 잘라서 올려 주세요.
- 기록지가 심하게 휘었거나 원근 왜곡이 큰 사진은 다루지 않습니다 (기울기만 보정).
- 타격각도 ±15°, ±30°, ±60° 의 보정은 보정표가 없어 근사값입니다.
- HEIC 사진은 일부 브라우저에서 열리지 않습니다 (JPG, PNG 사용).
- 계산식과 표는 KS F 2730 양식의 안내문과 표를 따랐습니다. 소속 기관의 기재 방식이 다르면 `app/js/calc.js` 를 조정하세요. 공식 인증을 받은 프로그램이 아니므로 **제출 전에 읽은 값과 계산 결과를 반드시 확인하세요.**
